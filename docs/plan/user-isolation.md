# 计划：用户隔离

## 采用的方案

方案 A。后端是 FastAPI 应用。用户标识是用户名。密码加盐后单向加密，写入 MySQL。登录是一个随机 token：Redis 保存它的哈希和用户名，前端放在 `localStorage` 里，请求头 `satoken` 带上。退出删掉 Redis 记录。JWT 工具留在用户模块里，浏览器登录不使用。前端没有登录就进入登录页。聊天记录的存储不做。原因见 `docs/decisions/001-login-session.md`。

## 改动的目录和模块

- `backend/app/users/`：用户模型、密码处理、JWT 工具、注册验证码、当前用户
- `backend/app/api/routes/`：注册、登录、退出、当前用户。只做入参校验和调用用户模块
- `backend/app/`：FastAPI 应用入口，启动时读配置并保证用户表存在
- `backend/config/`：`dev.yaml.example`。本机的 `dev.yaml` 不提交
- `backend/tests/`：读取测试环境配置。没有测试库时跳过
- `frontend/src/`：登录页、注册页、路由。未登录跳到登录页。聊天页的展示和发送不改
- `.gitignore`：忽略两份本机配置

不改 `agents`、`graphs`、`prompts`、`tools`。

## 实施步骤

每一步一次提交。上一步审核通过后再做下一步。

1. 配置与用户模型。读取 `dev.yaml`，缺字段或文件不存在时失败。同一台 MySQL 用 `database` 做开发库，用 `test_database` 做测试库。示例值留空，本机配置加入 `.gitignore`。用户表定义成模型，创建、读取、更新、删除写在模型基类上。用户名唯一，表里保存盐和加密结果。没有测试库时，对应用例跳过。
2. 密码。每条密码单独加盐，单向加密后得到盐和加密结果。用同一套盐和算法核对。不能从结果还原明文。
3. JWT 工具。用用户名签发，解析后只返回用户名。签名不对或过期则失败。
4. 注册。发送验证码时把验证码写入 Redis 和日志，接口不返回验证码。注册从 Redis 校验验证码后写入用户。用户名已存在或验证码错误则拒绝。这一步只做注册接口。
5. 登录。核对密码，通过后返回一个随机 token，Redis 只存它的哈希和用户名。退出删掉这条记录。当前用户只从 `satoken` 头对应的 Redis 记录取用户名，请求体里的用户名无效。未登录返回 401。密码错误不能登录。允许前端开发来源带上 `satoken` 头。这一步只做登录接口。
6. 前端注册页。填写用户名、密码和验证码并完成注册。不在这一步做登录跳转。
7. 前端登录页。token 放进 `localStorage`，请求带上 `satoken` 头。进入聊天页之前请求当前用户，401 或未登录则跳到登录页。登录成功进入聊天页，退出回到登录页。聊天页的消息展示和发送不改。

## 测试范围

- 配置缺字段时读取失败。
- 同一密码两次加密结果不同；用原盐可以核对；错误密码核对失败。
- JWT 能解析回原来的用户名；篡改、过期、错误密钥都失败。
- 两个用户：甲的 token 只能读到甲。请求体写乙的用户名仍然读到甲。未登录得到 401。退出后该 token 失效。
- 用户名已存在不能注册。验证码错误不能注册。密码错误不能登录。
- 验证码出现在日志中，不出现在接口响应中。
- 注册页可以提交注册。没有登录信息时显示登录页；登录成功后显示聊天页。
- 已有的聊天测试仍然通过。

## 不做的内容

不建会话表，不把聊天记录写入 MySQL，不改气泡、流式输出和输入框的行为。不接真实短信网关。不做刷新令牌。登录态的作废靠删除 Redis 记录，不另做一份长期 token。
