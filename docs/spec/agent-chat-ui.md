# 规格：基础 agent 聊天界面

## 行为说明

页面是一个聊天视图。上方是消息列表，下方是输入区。没有会话侧栏。

输入非空白文字并提交：

- 追加一条已完成的用户消息，正文为去掉首尾空白的输入。
- 追加一条助手消息，状态为 `streaming`，文本片段初始为空。
- 本地来源按固定间隔把回复写入这条助手消息的同一个文本片段。
- 全部写入后，该消息状态变为 `complete`。
- 流式期间输入区不可用，再次提交不会新增消息。

输入为空或只有空白时，不新增消息，来源不会启动。

来源报告失败时，助手消息状态变为 `error`，已写入的文字保留。输入区恢复，可以再次提交。

气泡只拼接 `text` 片段。`thinking`、`tool_call`、`mcp_call`、`human_input`、`context` 即使存在于数据中，也不显示。

## 接口、状态和模块边界

没有 HTTP 接口。文本来源由 `TextChunkSource` 提供，本地实现按间隔切分固定回复。以后替换为接口数据块时，仍调用同一条助手消息的追加方法。

消息状态：`complete`、`streaming`、`waiting_human`、`error`。这次实际出现的是前三个里的 `complete`、`streaming` 和失败时的 `error`。

## 验收标准

- 能输入并发送，助手回复在同一个气泡中逐段出现。
- 流式期间不能再次发送。
- 空白输入没有效果。
- 失败后可以再次发送。
- 页面不使用 hover 上浮、位移、放大或抬起阴影。
- 界面使用 `BubbleList` 和 `XSender`。

## 测试场景

- 正常路径：发送后两条消息，助手文本随片段增长并完成。
- 边界：空字符串、纯空白、流式期间重复发送。
- 失败：来源报错，状态为 `error`，随后可以发送下一条。
- 已有行为：非文本片段不进入展示正文。
