# 规格：用户隔离

## 行为说明

用户标识是用户名。密码明文不入库。每条密码单独生成盐，加盐后单向加密，表里保存盐和加密结果。登录用同一套盐和算法核对，不能从库里还原明文。

注册：

- 发送验证码时，按用户名生成验证码，写入 Redis，并写入日志。响应只有「已发送」，不含验证码。用户名已注册则拒绝。
- 提交用户名、密码、验证码。验证码正确才写入用户。验证码错误或用户名已存在则拒绝，不写入。

登录：

- 用户名和密码正确时生成一个随机 token，只在响应正文里返回一次。Redis 保存该 token 的 SHA-256 和用户名，过期时间用 `jwt.expires_minutes`。不保存 token 原文。
- 密码错误或用户不存在时拒绝，不写 Redis，响应里没有 token。

退出删掉 Redis 里的这条记录。复制走的 token 立刻失效。

读取当前用户时，用户名只来自请求头 `satoken` 对应的 Redis 记录。没有 token、记录不存在、已过期、用户不存在，都返回 401。请求体里另给一个用户名也不改变结果：甲的 token 只能得到甲。成功读取时把过期时间重新设为 `jwt.expires_minutes`。

前端把 token 放在 `localStorage`，之后的请求在 `satoken` 头里带上。打开聊天页之前先请求当前用户。没有登录或返回 401 时进入登录页。登录成功进入聊天页。退出后回到登录页。注册页只负责注册。聊天页里消息的展示和发送方式不变，内容按文本显示。

聊天记录不写入数据库。

## 接口、状态和模块边界

配置文件：

- `backend/config/dev.yaml`：`mysql`、`jwt` 与 `redis` 写在同一个文件。数据库字段为 `host`、`port`、`user`、`password`、`database`、`test_database`。JWT 字段为 `secret`、`expires_minutes`。Redis 字段为 `host`、`port`、`password`、`database`、`test_database`。`database` 是开发库，`test_database` 是同一台实例上的测试库。Redis 密码可以为空。
- 缺文件或缺字段则读取失败。仓库只提交 `dev.yaml.example`，值为空。本机文件不提交。

用户表由用户模型创建。用户名唯一。列包含用户名、盐、密码加密结果。创建、读取、更新、删除使用模型上的方法。

JWT 工具在 `backend/app/users/`，不在 `backend/app/tools/`。它只提供按用户名签发和解析出用户名。浏览器登录不使用它。

HTTP 由 `api/routes` 校验入参并调用用户模块，不调用 workflow。除排除名单外，请求先鉴权。排除的是发送验证码、注册、登录和退出：

| 动作 | 需要登录 | 成功 | 失败 |
| --- | --- | --- | --- |
| 发送验证码 | 否 | 已发送 | 用户名已存在 |
| 注册 | 否 | 用户已创建 | 验证码错误，或用户名已存在 |
| 登录 | 否 | 返回 token | 用户名或密码不正确 |
| 退出 | 否 | 删除 Redis 会话 | — |
| 当前用户 | 是 | 返回该用户名 | 401 |

开发时允许前端来源调用接口，并允许 `satoken` 请求头。

## 验收标准

- 两个用户不能通过对方的 token 读到彼此。
- 当前用户不接受请求体中的用户名。
- 验证码只出现在日志中。
- 未登录访问聊天页时看到登录页。
- 登录成功后看到原来的聊天页，气泡和输入行为与现在一致。
- 本机 MySQL 密码和 JWT 密钥不在仓库中。

## 测试场景

- 正常路径：发送验证码、注册、登录、读取当前用户、退出后再读得到 401。
- 边界：缺配置字段、空用户名、重复注册、错误验证码、错误密码。
- 失败：未知或过期的 token 得到 401；甲的 token 加上乙的用户名仍然得到甲。Redis 里看不到 token 原文。
- 密码：同一明文两次加密结果不同，原盐可核对，错误密码失败。
- 已有行为：现有聊天测试通过。没有本机 `dev.yaml` 或测试库不可用时，依赖测试库的用例跳过。
